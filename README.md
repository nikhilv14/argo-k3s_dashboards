# argo-k3s_dashboards

GitOps control-plane repo for the k3s homelab, managed via ArgoCD app-of-apps.

## Bootstrap (one-time, manual)

    kubectl apply -f bootstrap/root-app.yaml

The `root` Application syncs everything under `argocd/`. Every other change
to the cluster is made through Git — do not `kubectl apply` workloads or
`helm install/upgrade` directly.

## Layout

| Path | Purpose |
|---|---|
| `bootstrap/root-app.yaml` | The app-of-apps Application (only manual apply) |
| `argocd/projects.yaml` | ArgoCD AppProjects: immich, quick-apps, dashboards, infra |
| `argocd/apps-*.yaml` | All Application definitions, ordered by sync-wave. Keep this dir FLAT: ArgoCD's directory generator silently skips subdirectories named `apps` |
| `infra/*/values.yaml` | Helm values for adopted infra charts |
| `longhorn/recurring-jobs.yaml` | Longhorn RecurringJob CRs (CronJobs are generated by longhorn-manager) |
| `cloudflared/`, `kubernetes-dashboard/`, `longhorn-dashboard/` | Dashboard / edge-access manifests |

## Applications and sync order

| Wave | Apps |
|---|---|
| 0 | cert-manager, sealed-secrets, metallb, csi-driver-nfs, immich-storage |
| 1 | longhorn, immich-database |
| 2 | ingress-nginx, immich-app |
| 3 | immich-monitoring |
| 10 | cloudflared, longhorn-dashboard, kubernetes-dashboard, tandoor |

ArgoCD itself remains Helm-installed by design (day-0 bootstrap); all other
infrastructure was adopted from Helm releases into ArgoCD with
`ServerSideApply=true`. Do not `helm upgrade` the adopted releases.
